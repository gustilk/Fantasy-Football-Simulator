# Projection engine upgrade (Phase 1 + Phase 2)

Free data only: ESPN public site data and nflverse downloads. No paid feeds, no API keys, no rebuild —
everything below extends the existing modules and is additive (old saved forecasts load unchanged).

## Phase 2 — distribution, correlation and availability

The football-evidence layer already blended targets, carries, snap share, air yards, red-zone and
goal-line usage, EPA matchups, spreads and totals (`football-evidence.ts`, `market-odds.ts`). **The core
game model was deliberately not changed**: there is no held-out accuracy evidence to justify new
coefficients, and changing it would alter replays of frozen forecasts.

What was added (`lib/projection-distribution.ts`, wired in `lib/ensemble.ts`):

* **Distribution** per player: mean, median, P10, P75, P90, P95, Monte Carlo standard error of the mean,
  and **bust probability** (probability of scoring under a fixed floor: QB 12, RB 6, WR 6, TE 4 DK points;
  editable in `BUST_FLOOR_POINTS`; a heuristic, not a validated standard). Market / high-scoring weights are
  respected. Quantiles use nearest-rank, so they can differ slightly from the legacy P10/P90 fields, which are
  unchanged.
* **Correlations** measured across the simulated games: QB with own receivers and backs, back with receivers,
  and opposing pairs. Stored on `ensemble.correlations`.
* **Availability uncertainty**: for a player with a verified Questionable/Limited/Doubtful designation, an
  extra "availability-adjusted" distribution mixes in the chance of a 0-point no-show, using historical play
  rates by designation and position (`lib/availability-rates.ts`, generated by
  `scripts/derive-availability-rates.py` from nflverse injury reports + snap counts, 2021–2025 regular
  seasons; e.g. Questionable WR 69% played, Questionable QB 37%, Doubtful ~0%, Out ~0%). Unknown gets no
  adjustment. The main summary stays "if active".
* **Saved forecasts and the UI** carry the new fields when present. DraftKings board → Details shows the
  extra columns and a legend separating *historical data*, *calculated projections* and *verified
  availability*. Forecasts saved earlier show "not in this older forecast"; nothing is back-filled.

To refresh the availability rates: download `injuries_<year>.csv`, `snap_counts_<year>.csv` and `players.csv`
from the nflverse-data releases, then run `python3 scripts/derive-availability-rates.py <dir> <first> <last>`.

## Remaining limitations (be honest about these)

* **Opposing-player correlation is about zero** in the current simulator (measured ≈ 0.01), while real
  shootouts lift both offenses. QB-to-own-receiver correlation (≈ +0.38) and QB-to-back (≈ +0.18) look plausible.
  Fixing this needs a shared game-environment factor inside the simulator, behind a new opt-in input
  version so frozen forecasts replay identically.
* Projections are **not backtested**. With 200 simulations, P95 and bust probability are noisy (see the
  standard error and use more runs when it matters). Pair correlations from 200 games are also noisy.
* Availability rates are base rates by designation and position, not a model of the individual. ESPN's
  "limited" is treated like nflverse's limited practice with no game designation, a looser match.
* Snap counts, air yards, red-zone and goal-line signals were already used; this work did not add new signals
  or validate their weights.
* No pre-kickoff inactive list (usually ~90 minutes before kickoff) is fetched; check it before submitting.
* Two older script tests were already failing before this work and are outside its scope:
  `scripts/division-matchup-test.ts` (head-to-head pass yards come out 256.46, test expects 295; cause not
  investigated) and `scripts/draftkings-accuracy-test.ts` (`Cannot find package 'react'` when run from `scripts/`). The 150-lineup
  portfolio optimizer was not touched.
